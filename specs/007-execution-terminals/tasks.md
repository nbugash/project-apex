**Input**: Design documents from `/specs/007-execution-terminals/`

**Prerequisites**: [plan.md](./plan.md), [research.md](./research.md), [data-model.md](./data-model.md),

**Tests are required, not optional.** Constitution Principle VII binds every feature to unit,
integration and end-to-end levels, FR-033 requires every behaviour to be verifiable with no remote
host and no network, and A-TEST makes the standard binding. Test tasks below are deliverables.
[quickstart.md](./quickstart.md)'s 30-row success-criterion table is the test inventory; its nine
negative checks (§9) and eight mutations (§10) are deliverables of their own.

**Every quantity below is [plan.md](./plan.md)'s *Fixed Quantities*.** No task chooses a number,
and no test types one in: the chunker's size bound, the chunker's time bound, the retention bound,
the fairness gate's consecutive-yield bound and the panel's history bound are all read from the
constant the source exports (quickstart §8).

## Format: `[ID] [P?] [Story] Description`

## Path Conventions

Rust workspace: `protocol/`, `engine/` (crate `apex-engine`), `client/core/` (crate `apex-shell`).
Webview: `client/ui/lib/<area>/` — **there is no `src/` level**. Rust test helpers live in each
crate's `tests/common/`. Webview unit specs are in `tests/unit/` at the repository root, not under
`client/ui/`. End-to-end specs: `tests/e2e/`. Performance specs: `tests/perf/`. Fixture programs
are Cargo examples under `engine/examples/`, built by `cargo build --examples` and spawned from
`target/debug/examples/`. Engine MSRV is **1.75** and the engine adds **no async runtime** — **no
`async fn` appears in any engine task below**.

### The frame writer's fairness gate — §4.6 in the direction F010 floods

- [X] T032 Implement the fairness gate in `engine/src/adapters/outbound/frame_writer.rs`: keep the existing mutex and add a **count of waiting interactive writers** beside it, under its own lock with a condvar. `write_interactive` raises the count, takes the write mutex, writes one frame, lowers the count and **wakes the waiters**; `write_bulk` waits on that condvar while the count is non-zero, then takes the write mutex exactly as `write` does today; after **8 consecutive yields** — a named `pub const` T034 reads, from plan.md's *Fixed Quantities* row *Consecutive yields before a bulk frame* — a bulk writer stops yielding and writes, which is what keeps a strong preference from becoming a monopoly. §4.6 requires interactive traffic to win the race to the wire in both directions and states that the engine does **not** queue: a queue would end the blocking that FR-013's backpressure is made of, and let an exit overtake the output it must follow. - [X] T032c Add the single escalation thread in `engine/src/adapters/outbound/task_threads.rs` owning a deadline set: `TaskService` registers a deadline and **notifies the set's condvar**, the thread waits on that condvar while its set is empty and on `Clock::sleep_until` once it holds one, and sends `SIGKILL` to the process group of any task still alive when `now >= deadline`. Two further properties, each of which is a defect if it is left out:

It waits unbounded on its own condvar while the set is empty, so an idle engine wakes not at all, and on a bounded wait while a deadline is pending, so `close` interrupts it and a settable clock that does not notify this condvar is still observed. The poll interval bounds only how *late* a kill may be and is not a plan quantity; the five seconds a developer is promised is.

The entry therefore carries either a `Weak` handle to the task it was registered for — dead by the time the thread wakes, so the entry is dropped — or the `(TaskId, Pid)` pair it was registered with, compared against the live task **before** signalling and skipped on a mismatch. And `release` **cancels** the deadline, so the common case never reaches the comparison at all

## Implementation strategy

**MVP is Setup + Foundational + US1 (T001–T066, T050a and T066a included).** It delivers the feature's whole point — a
command runs on the host and the developer watches it work, in a panel themed from the prototype —
and it is independently shippable. Note that the MVP is unusually expensive here because three
things plan.md found are foundational rather than story work: the engine cannot receive a
notification at all today, the outbound direction prefers nothing over anything, and a workspace cannot be
deregistered. None of the three is US1's, and all three block it.

Stop after US1 and the terminal is a live log. US2 makes it a terminal. US3 makes it honest about
how things ended and stops it leaking processes. US4 is the one that proves the architecture — it
is the first feature to put real volume through F004's writer seam, and SC-006 is the criterion
that would otherwise fail alone while everything else passed. US5 is what makes a dropped link
survivable.
